01 / 主项目

Pi Zaya

Windows 测试版

从多篇论文里找到答案，并定位到证据

读同一方向的多篇论文时，先问一个具体问题，再沿回答中的引用回到原文；需要横向比较时，把方法、实验与局限整理进证据矩阵。

PythonFastAPIReactRAG
做什么
本地学术文献工作台，将 PDF 阅读、论文问答、跨文献比较和研究笔记连接起来。
我做了什么
负责产品设计、PDF 结构化解析、检索与 Agent 工具集成、React 阅读界面和 Windows 交付；作为唯一开发者，使用 AI 辅助编码并承担调试、验证责任。
最难的地方
PDF 中的页码、公式与段落必须在解析后仍可定位。检索得到的片段还要能支撑具体结论，让用户看清“回答依据是什么”与“哪里还缺证据”。
可查看的成果
已发布 Windows 测试版，无需自行安装 Python。可查看仓库、使用文档和演示界面，体验文献问答及引用定位。
下载 Windows 版 ↗GitHub ↗项目介绍 →
技术实现与验证边界
  • 解析层保留页面与结构线索，检索、回答和阅读器定位围绕同一来源组织，减少结论与原文脱节。
  • 采用 BM25 检索与 Agent 工具调用；本地开发中的 BM25＋Dense / RRF 能力限定在单篇及文献篮范围，不等同于全库默认混合检索或所有发布版本都已具备。
  • 跨论文比较需核对任务、数据集、设置与指标；资料不足时保留缺口，不能以模型补全代替原文证据。
02 / 企业命题

面向 EDA 扫描链插入的 LLM Agent

广立微命题 · 比赛进行中

把需求解析、工具执行与结果验证串成闭环

扫描链插入不是生成一份脚本就结束。Agent 需要理解设计约束、执行工具，依据报错修复，并检查最终网表与交付产物是否满足要求。

PythonLLMDockerYosys / EQY
做什么
扫描链插入与脚本修复 Agent，读取设计要求、网表和单元库，生成脚本并根据 EDA 工具反馈修复。
我做了什么
负责需求拆解、Agent 与工具集成、证据引用与修复状态管理、执行预算控制、调试及验收。
最难的地方
模型给出的修复可能引用错误依据、基于过期状态，或只消除表面报错。通过引用校验、哈希绑定和版本化状态，限制修改范围并保护已验证结果。
可查看的成果
完成公开案例的端到端运行与交付验证。该结果不代表隐藏题满分、获奖、工业级通用能力或签核结论。
查看工作流程 →
技术实现与验证边界
  • 模型提出命令与局部补丁，确定性程序检查引用、约束及修复基线；工具反馈再进入诊断与修复流程。
  • 结构网表解析保留兼容回退，在统一时间与资源预算内受控重叠任务。单次性能对照不代表稳定加速。
  • 公开案例端到端运行与交付验收有记录；等价验证受所用模型与配置范围限制，不外推为任意设计、时序或工业签核结论。

证据约束诊断

诊断关联可核查的证据引用，区分观察与推断，避免无依据的修复结论。

修复状态可追溯

用哈希绑定输入与候选，版本化保存修改；失败提案不覆盖已验证状态。

有边界的执行效率

结构网表解析配合兼容回退，在统一预算下受控重叠任务；不将单次对照当作稳定加速承诺。

03 / 持续研究

Pi Research

在线演示

从一次论文搜索，走向持续的研究跟踪

围绕一个研究问题持续收集论文，阅读推荐理由并记录接受或排除反馈，再把积累的文献组织成研究地图和后续学习路径。

TypeScriptReactWorkers / D1
做什么
面向研究方向的论文发现工具，连接多源检索、个性化筛选、阅读反馈与研究跟踪。
我做了什么
负责多源检索与候选去重、模型筛选、异步任务与进度恢复、研究空间持久化和前端交互；作为唯一开发者，结合 AI 辅助完成实现与验证。
最难的地方
长任务会受到来源限流、网络中断和模型调用失败影响。需要保留已完成进度与候选来源，并将明确偏好和系统推断分开，避免重复工作和研究方向漂移。
可查看的成果
提供可匿名打开的在线演示和公开仓库。研究空间保存文献与反馈；模型驱动的功能需配置相应服务。
在线演示 ↗GitHub ↗
技术实现与验证边界
  • 用持久化任务进度记录已探索的来源和候选，让重试能够接续已完成工作。
  • 研究空间把论文、筛选反馈和方向信息放在同一上下文中，推荐需要给出阅读理由。
  • 数据源覆盖与推荐结果会受接口可用性、研究问题和模型配置影响；研究地图不表示穷尽整个领域。
04 / 科研工具

Edge 商店已上架

在阅读现场翻译，保留学术内容的结构

阅读网页、Overleaf 或双栏 PDF 时，选取需要理解的段落，就地查看译文；遇到公式或扫描区域时，按内容类型选择结构保护或视觉识别。

TypeScriptManifest V3PDF.js
做什么
面向科研阅读与写作的 Edge 扩展，支持划词、全文、区域翻译及原文译文对照。
我做了什么
负责扩展交互、PDF 阅读集成、LaTeX 结构保护、长文本分段与流式输出、中断续译及商店发布；作为唯一开发者，使用 AI 辅助实现并负责调试。
最难的地方
双栏阅读顺序、跨行选区、公式与自然语言混排都会影响翻译。需要识别实际选区、保护公式结构，并在长任务中保留进度，让用户能核对与继续编辑。
可查看的成果
已上架 Edge 商店，提供公开代码和安装说明。用户可自行配置兼容 API，文字翻译与图像识别按需求选择模型。
Edge 商店 ↗GitHub ↗
技术实现与验证边界
  • 区分可翻译的自然语言与需要保留的 LaTeX 结构；翻译结果仍需结合原文检查术语和含义。
  • PDF 文字选区优先使用文字处理，扫描或复杂图像区域由用户确认范围后使用视觉模型。
  • 按分段组织长文本与流式输出，减少阅读等待；具体能力随网页结构、PDF 文字层和模型服务而变化。
