NLP 基础：文本编码、表示学习与语言模型

发表于2026-09-12|更新于2026-09-12|NotesAI Agent

封面：冰岛冰川河流入海 · 摄影 Andro Loria / National Geographic Your Shot

同一句“设备无法联网”，可以作为搜索查询、故障类别的输入，也可以成为一段回答的开头。文字没有变，计算机需要完成的运算却不同：有时比较文档，有时预测标签，有时估计接下来可能出现的 token。

这些任务共用一些基础：把文本编码为离散符号，为符号建立数值表示，再利用上下文完成预测。编码保留了什么信息、表示丢掉了什么信息、训练目标奖励什么行为，会一直影响到最终结果。

本篇以 Happy-LLM 第一章 为起点，补充文本编码、表示学习与检索之间的联系。

文本处理中的四个层次

字符与 token 决定输入单元；向量表示让符号可以参与计算；语言模型学习上下文中的概率关系；分类、检索和生成把这些能力用于不同输出。

1. 文本进入模型之前：字符、token 与词表

1.1 字符编码与模型编码是两回事

文本文件首先是一串字节。UTF-8 等字符编码规定字节怎样对应 Unicode 字符；tokenizer 则规定这段文本怎样对应模型词表中的 token ID。UTF-8 解码正确，并不意味着已经完成模型输入编码。

“字符数”本身也有不同口径：Unicode 码点、用户看到的字形、UTF-8 字节数可能不相等。例如某些 emoji 由多个码点组成。对模型而言，最终参与计算的长度是 token 序列长度，不能直接用字节数或界面显示的字符数代替。

预处理同样会改变信息。统一全角/半角可能有助于检索；把所有标点、数字或否定词删掉，却可能破坏设备型号、代码片段和“不允许执行”这样的约束。应根据任务决定规范化规则，并保留可追溯的原文。

1.2 分词与子词切分

中文分词通常寻找语言学上的词边界。LLM 的 tokenizer 则将文本转换成有限词表中的 ID，切分可能落在子词、字节或字符边界上。一个汉字几个 token、英文单词是否完整保留，都取决于具体 tokenizer。

ID 是离散索引。不能用 abs(id1 - id2) 判断词义是否接近。

1.3 为什么不直接把整个词当一个 token

如果每个完整词都是词表项，常见词处理起来很方便，但型号、人名、拼写变体和新组合会持续产生。未收录的词只能退回未知词标记，细节可能丢失；持续扩大词表又会增加 embedding 表与输出分类层的体积。

如果完全按字符或字节编码，覆盖面更容易做大，但序列可能变长。后面会学到，稠密注意力在序列维度上有平方项，因此 token 数不仅影响接口计费，还会影响计算和显存。

子词方法在两者之间折中：频繁片段用较长单元表示，罕见词分解成可复用的小单元。“能编码”与“懂含义”是两件事：把陌生型号拆成若干 token，只解决了输入覆盖问题，模型仍可能不知道型号对应什么产品。

1.4 BPE 的核心直觉

BPE 的训练从较小的符号开始，统计相邻符号对，将高频的符号对合并成新符号，反复进行。使用时依据已学到的合并规则切分文本。它优化的是一种可复用的编码方式，不保证切成词根或真实单词。

为了手算，可以设训练片段为 low low lower，从字符开始。如果先合并 l + o → lo，再合并 lo + w → low，那么 lower 可能表示为 low | e | r。这只是简化示例；真实实现还可能有字节编码、预切分、特殊 token 和不同的合并规则。

WordPiece、Unigram 也解决有限词表如何覆盖文本的问题，但训练和分割准则不同。SentencePiece 是分词工具库，可以支持 BPE、Unigram 等模型，不应与它们完全并列为同一种算法。见 SentencePiece 官方说明。

1.5 词表大小带来的取舍

编码单元 主要优点 主要代价
完整词 常见词序列较短，边界直观 新词和拼写变体容易落到词表外
字符或字节 基础单元覆盖面大 序列可能变长，计算位置更多
子词 高频片段紧凑，低频组合可拆分 边界不一定符合词义，仍依赖具体词表

在隐藏维度 d 固定时，大小为 V 的 embedding 表约含 Vd 个参数；生成模型的词表投影也与 V 有关，某些模型会共享输入/输出权重。扩大词表可能缩短序列，却会增大表与输出分类空间，不能只看其中一个数字。

tokenizer 的词表、合并规则、特殊 token 和模型权重必须配套。相同 ID 在另一套词表中可能表示完全不同的片段；“两套词表大小相同”也不能保证可互换。

2. 稀疏表示：把符号变成可计算的特征

2.1 One-hot、词袋和 TF-IDF：三个不同概念

设词表是 [示波器, 联网, 报修, 电源]。

One-hot 描述一个离散项；词袋汇总一段文本中的出现次数。如果只记录是否出现，则是二值词袋。词袋通常丢失顺序，因此“设备支持联网”和“设备不支持联网”如果预处理丢了“不”，就可能变得难以区分。

TF-IDF 给常见于当前文档、但不普遍出现于整个语料的词更高权重。一种平滑版本是：

TFIDF⁡(t,d)=tf⁡(t,d)(ln⁡1+N1+df⁡(t)+1).\operatorname{TFIDF}(t,d)=\operatorname{tf}(t,d)\left(\ln\frac{1+N}{1+\operatorname{df}(t)}+1\right). TFIDF(t,d)=tf(t,d)(ln1+df(t)1+N​+1).

这里 tf⁡(t,d)\operatorname{tf}(t,d)tf(t,d) 是词 t 在文档 d 中出现的次数，N 是文档总数，df⁡(t)\operatorname{df}(t)df(t) 是包含 t 的文档数。

不同实现可能使用相对词频、对数词频或归一化，因此比较实验时应固定定义。

2.2 把 TF-IDF 手算一次

使用已经分好词的三篇小文档：

这里有 3 篇文档。“示波器”“网络”“故障”的文档频次都是 2；“电源”“连接”“检查”的文档频次都是 1。沿用上面的平滑定义：

idf⁡(t)=ln⁡1+N1+df⁡(t)+1.\operatorname{idf}(t)=\ln\frac{1+N}{1+\operatorname{df}(t)}+1. idf(t)=ln1+df(t)1+N​+1.

于是 idf⁡(网络)=ln⁡(4/3)+1≈1.2877\operatorname{idf}(\text{网络})=\ln(4/3)+1\approx1.2877idf(网络)=ln(4/3)+1≈1.2877，idf⁡(电源)=ln⁡(4/2)+1≈1.6931\operatorname{idf}(\text{电源})=\ln(4/2)+1\approx1.6931idf(电源)=ln(4/2)+1≈1.6931。更稀有的“电源”权重更大；本例每个词只出现一次，所以词频都是 1，TF-IDF 数值就是 IDF 数值。

按词表 [示波器, 网络, 故障, 电源, 连接, 检查]，文档 d1d_1d1​ 的未归一化向量是 [1.2877,1.2877,1.2877,0,0,0][1.2877,1.2877,1.2877,0,0,0][1.2877,1.2877,1.2877,0,0,0]。若做 L2 归一化，三个非零分量都会变成约 0.5774。

这里“稀疏”不是指向量维度小，而是大部分维度等于零。实际实现通常用稀疏矩阵保存非零项及其索引，避免为每篇文档存储整个词表长度的浮点数组。

稀疏表示的好处是可解释、能抓住精确术语。缺点是“无法联网”和“网络连接失败”没有相同关键词时可能匹配不好。对于设备型号、错误码和文件名，精确匹配仍然很有价值。

3. 语言模型：为序列建立概率分布

语言模型为序列赋予概率。概率链式法则把整句概率分解为条件概率的乘积：

P(x1,…,xn)=∏t=1nP(xt∣x<t).P(x_1,\ldots,x_n)=\prod_{t=1}^{n}P(x_t\mid x_{<t}). P(x1​,…,xn​)=t=1∏n​P(xt​∣x<t​).

x<tx_{<t}x<t​ 表示第 t 个 token 之前的整个前缀，乘积符号表示把各个位置的条件概率相乘。

N-gram 做了截断近似，只看前面 N−1 个词。例如 trigram 估计 P(失败 | 网络, 连接)。统计计数越细，数据越稀疏；没见过的组合容易得到零概率，因此需要平滑或回退。

3.1 链式法则是精确分解，N-gram 才是近似

对“网络 连接 失败”这三个词，链式法则给出：

P(网络,连接,失败)=P(网络)P(连接∣网络)P(失败∣网络,连接).P(\text{网络,连接,失败})=P(\text{网络})P(\text{连接}\mid\text{网络})P(\text{失败}\mid\text{网络,连接}). P(网络,连接,失败)=P(网络)P(连接∣网络)P(失败∣网络,连接).

这一步不需要独立性假设。Bigram 模型才会把最后一项近似成 P(失败∣连接)P(\text{失败}\mid\text{连接})P(失败∣连接)，舍弃更早的“网络”。真实模型还会处理句首、句尾标记，这里为了展示分解而省略。

如果训练语料里“连接”后面共出现 10 个词，其中 4 次是“失败”，最大似然估计得到 P(失败∣连接)=4/10P(\text{失败}\mid\text{连接})=4/10P(失败∣连接)=4/10。若某个后继词从未出现，其概率就是 0；整个序列概率相乘时也会变成 0，即使这句话在语言上完全合理。

加一平滑可以写成：

P(w∣h)=C(h,w)+1C(h)+∣V∣.P(w\mid h)=\frac{C(h,w)+1}{C(h)+|\mathcal V|}. P(w∣h)=C(h)+∣V∣C(h,w)+1​.

它给未见组合分配了一点概率，但当词表很大时可能过度稀释高频项，因此这里主要用来理解“为未见事件留出概率质量”的思想，不作为所有语言模型的最佳估计法。

3.2 损失函数如何把预测变成训练信号

神经语言模型用参数化网络估计条件概率，能利用共享表示泛化。自回归训练中，一段序列同时提供多个预测任务：

交叉熵 −log P(正确下一个 token) 鼓励模型提高正确标签的概率。平均交叉熵取指数得到困惑度；只有在 tokenizer、评测数据和统计口径一致时，困惑度才适合直接比较。

把句子中的有效预测位置记为 1,…,T1,\ldots,T1,…,T，平均负对数似然为：

L=−1T∑t=1Tln⁡Pθ(xt∣x<t),PPL⁡=eL.\mathcal L=-\frac1T\sum_{t=1}^{T}\ln P_\theta(x_t\mid x_{<t}),\qquad \operatorname{PPL}=e^{\mathcal L}. L=−T1​t=1∑T​lnPθ​(xt​∣x<t​),PPL=eL.

若三个正确 token 的预测概率依次为 0.5、0.25、0.5，则平均损失约为 0.9242，困惑度约为 2.52。它可以理解为模型在这些位置上的一种平均不确定性量度，不是“每次都会在 2.52 个词里随机选一个”，更不是错误率 2.52%。

代码里要特别小心标签对齐：输入第 ttt 个位置的输出应该对比第 t+1t+1t+1 个 token。若错误地对比当前位置，很可能训练出了复制输入的捷径。Padding 或不参与监督的位置也要在损失里排除；某些训练库已内置标签右移，调用方不能再重复移动一次。

困惑度衡量的是模型对测试文本的预测能力，无法单独评价事实正确性、检索质量或执行结果。生成一段流畅说明与完成一个实际任务，需要不同的评测。

3.3 从计数表到神经网络

N-gram 为不同上下文分别统计计数。上下文越长，可能出现的组合越多，许多组合在语料里根本没有出现过。神经语言模型用共享参数处理上下文，让不同样本通过共同的表示与网络发生联系：

ht=fθ(x≤t),zt=htW+b,Pθ(xt+1∣x≤t)=softmax⁡(zt).h_t=f_\theta(x_{\le t}),\qquad z_t=h_tW+b,\qquad P_\theta(x_{t+1}\mid x_{\le t})=\operatorname{softmax}(z_t). ht​=fθ​(x≤t​),zt​=ht​W+b,Pθ​(xt+1​∣x≤t​)=softmax(zt​).

这里 f 可以是固定窗口网络、循环网络或 Transformer。它们对上下文的组织方式不同，但都可以用下一个 token 的交叉熵来训练。训练目标与网络架构是两个维度：不能把“使用 Transformer”和“使用自回归目标”当成同一个概念。

反向传播会把预测误差传回上下文网络和输入表示，因此 embedding 不需要手工设定含义。下一节从这张可学习的查找表开始，说明向量怎样形成。

4. 表示学习：从查找表到上下文向量

4.1 Embedding 查表具体做了什么

假设词表大小为 VVV，隐藏维度为 ddd，embedding 是一个可学习矩阵：

E∈RV×d,xt=E[idt,:]∈Rd.E\in\mathbb{R}^{V\times d},\qquad x_t=E[\mathrm{id}_t,:]\in\mathbb{R}^{d}. E∈RV×d,xt​=E[idt​,:]∈Rd.

E[17] 就是读取第 17 行。数学上，若 utu_tut​ 是长度为 VVV 的 one-hot 行向量，则 xt=utEx_t=u_tExt​=ut​E，但工程实现不用先创建一条巨大的 one-hot 再做矩阵乘法，直接索引即可。

一段长度为 TTT 的文本最终变成 X∈RT×dX\in\mathbb{R}^{T\times d}X∈RT×d；一批补齐到相同长度的文本变成 [B,T,d][B,T,d][B,T,d]。这就是第二章 Transformer 的输入起点。此时相同 token ID 查出的向量相同，上下文差异还要由后续网络处理。

4.2 Word2Vec：从上下文学习静态向量

Word2Vec 通过预测任务学习 embedding：CBOW 用周围词预测中心词，Skip-gram 用中心词预测周围词。训练结束后，可以取出词表中每个词的向量。

它让经常出现在相似上下文中的词获得有用的几何关系。但同一个词的基础词向量通常固定不变，“苹果手机”和“吃苹果”中的“苹果”会取出同一个向量。

标准 Word2Vec 没有为任意未登录词自动生成向量的能力。如果词不在词表中，需要额外策略；带子词机制的模型才有不同的处理办法。CBOW 学的是预测中心词的任务，也不是直接把“标准答案向量”作为监督标签。Word2Vec 原论文

用“示波器 出现 网络 故障”构造训练样本，窗口设为 1：当中心词是“网络”，CBOW 的输入是“出现”和“故障”，目标是“网络”；Skip-gram 则从“网络”构造“出现”“故障”这两个预测目标。滑动窗口会从大量句子产生许多这样的样本。

以 Skip-gram 为例，一种全词表 softmax 写法是：

P(wo∣wc)=exp⁡(uwo⊤vwc)∑w∈Vexp⁡(uw⊤vwc).P(w_o\mid w_c)=\frac{\exp(u_{w_o}^{\top}v_{w_c})}{\sum_{w\in\mathcal V}\exp(u_w^{\top}v_{w_c})}. P(wo​∣wc​)=∑w∈V​exp(uw⊤​vwc​​)exp(uwo​⊤​vwc​​)​.

vwcv_{w_c}vwc​​ 是中心词的输入向量，uwou_{w_o}uwo​​ 是目标上下文词的输出向量；训练中常有两套向量表。提高真实上下文的概率，会推动有关联的输入/输出表示形成有用结构。全词表求和很贵，因此负采样等方法会用替代目标降低训练成本；负采样本身不等于严格计算这个完整 softmax。

这里的表示来自预测任务，而不是人工逐维标注“第 1 维代表联网，第 2 维代表电源”。词向量某一维通常没有稳定、单独可命名的含义。Word2Vec 学到的是词表示，不能直接承担完整的自回归序列生成。

4.3 负采样改变的是训练目标

完整 softmax 对词表求和，每个样本都要考虑大量候选。Skip-gram 的负采样把一个真实词对与若干噪声词对区分开。一个正样本配 K 个负样本时，可写为最小化：

LNS=−log⁡σ(uo⊤vc)−∑i=1Klog⁡σ(−uni⊤vc).\mathcal L_{\mathrm{NS}}=-\log\sigma(u_o^\top v_c)-\sum_{i=1}^{K}\log\sigma(-u_{n_i}^\top v_c). LNS​=−logσ(uo⊤​vc​)−i=1∑K​logσ(−uni​⊤​vc​).

这里 σ(z)=1/(1+e−z)\sigma(z)=1/(1+e^{-z})σ(z)=1/(1+e−z) 是 sigmoid 函数。第一项鼓励真实上下文词对得分提高，第二项鼓励抽到的噪声词对得分降低。负样本来自指定分布，训练成本随采样数量而不是直接随整个词表增长。它是替代的二分类目标，不等于已经计算出归一化的全词表概率。Word2Vec 负采样论文

这类训练得到的“相似”通常更接近上下文使用方式相似。反义词也可能共享很多上下文，因此向量接近不能直接解释为两个词在逻辑上等价。

4.4 ELMo：同一个词随上下文改变

ELMo 使用双向语言模型，让一个位置的表示依赖左右上下文，下游任务可以组合不同层的表示。这解决了静态词向量无法直接区分同词不同语境的问题。

这里的“动态”指表示随输入上下文变化，不是推理时在更新模型参数。ELMo 是上下文化词表示的重要工作，预训练思想在它之前已经存在。ELMo 原论文

把“苹果发布新手机”和“苹果切成小块”分别输入，目标位置虽然都是“苹果”，两边的上下文不同，双向语言模型得到的隐藏表示也不同。下游任务可以利用这种差异，判断前者偏向组织名称、后者偏向食物。

它提供了一个重要学习思路：先设计能从无标注文本构造标签的预训练任务，再把中间表示迁移给下游任务。预训练不是“完全没有监督信号”，而是监督目标常常来自文本自身，例如下一个词或上下文。

4.5 上下文表示依赖什么计算结构

循环网络逐位置更新状态，例如 ht=f(xt,ht−1)h_t=f(x_t,h_{t-1})ht​=f(xt​,ht−1​)，于是当前位置能间接接收此前的信息。LSTM 通过门控管理状态与信息保留，缓解普通 RNN 的部分长程依赖问题，但同一条序列内仍存在状态更新的先后依赖。

ELMo 分别运行前向与后向语言模型，并组合相应位置的表示。前向模型看左侧上下文，后向模型看右侧上下文；不是让某一个自回归方向在预测时偷偷看到未来。下游读取组合特征时，输入文本本来就已给定，因此可以使用两侧信息。

Transformer 后来换了一种信息交流方式：让一个位置直接对可见位置计算注意力，而不必只通过相邻状态传递。输入 embedding、上下文表示、句向量的区别仍然存在，并不会因为网络换成 Transformer 就消失。

5.1 token、上下文与整段文本的表示

把任意生成模型的最后一层做平均，并不自动得到好的检索向量。检索需要合适的训练目标、池化方式，以及查询和文档编码约定。

另外，双向上下文表示与自回归生成的可见范围不同。ELMo 的下游特征可以结合左右信息；而一个正在生成下一个 token 的模型不可能访问尚未生成的未来文本。第二章的因果遮罩就是为了在训练时保持这个约束。

更关键的是训练目标。句向量模型常使用匹配或对比目标，使相关的查询与文档靠近、无关样本分开。查询与文档还可能需要不同前缀或编码约定。生成模型的隐藏状态虽含上下文信息，却未必为这样的距离比较优化。Sentence-BERT

6. 从表示到任务：输出结构决定建模方式

6.1 分类、标注、抽取和生成

不能将所有任务都用 token 准确率衡量。一个三字人名只标对两个字，可能有较高逐字准确率，却没有提取出任何完整人名；实体级 precision/recall 要同时检查跨度和类别。

6.3 方法演进没有消除这些边界

规则方法把知识写进规则，统计方法从数据估计特征与概率，神经模型进一步学习表示，预训练让表示能够迁移到不同任务。它们可以在一个系统里共存：正则校验编号，关键词检索查错误码，向量检索处理同义改写，生成模型组织答案。

选用哪种方法，取决于输入变化、错误代价、可用数据和资源约束。复杂模型不一定比一个明确的规则更适合精确格式校验。

每一步都改变下一步能使用的信息。没有解析出来的表格无法被正确分块，没有进入候选集的证据无法由重排补回，被截断的来源也无法支持最后的引用。

7.1 解析、分块、召回与生成

文档解析首先决定信息有没有被读进来。PDF 的两栏错序、表格跨行断裂、图片里的告警代码没被识别，都不是换 embedding 能自动解决的问题。应保存解析前后的抽样对照，并保留文档 ID、页码、标题等来源信息。

分块决定一次召回携带多少上下文。太小可能只召回“按此按钮”，丢失按钮名称与前置条件；太大可能把大量无关段落一起塞进提示，还降低一段文本表示的针对性。重叠窗口可以降低边界断裂，但会引入重复，所以要同时考虑去重与 token 预算。

召回追求把可能相关的候选找进来；重排进一步对问题与候选之间的匹配做判断。它们承担不同职责，增加重排不意味着可以忽略召回遗漏：没有进入候选集的段落，重排器无从补回。

答案构造要保存证据映射：回答引用的段落 ID 必须能追溯到真实文档。模型输出 [3] 只是一个字符串，程序应该检查它是否属于本次提供的来源集合。查到证据与依据证据正确回答仍是两个步骤。

7.2 稀疏与稠密检索的互补

“错误 E1042”与“错误 E1043”在自然语言形式上很相似，但业务意义可能完全不同。向量检索擅长某些语义改写，不保证对每一个数字或型号严格区分。关键词检索则能为这些精确符号提供补充。

一个简单混合策略是分别召回候选，再按排序融合。不要把 BM25 分数和余弦相似度未经校准直接相加，它们的尺度不同。无论使用何种融合办法，都需要在自己的问题集上检查收益，尤其是精确编号问题和语义改写问题这两类。

不能仅凭几道展示题选方案。保存一批带“相关段落 ID”和“预期行为”的问题，划分开发与保留测试集。先计算 Recall@k = 前 k 条召回中的相关段落数 / 全部相关段落数，再评估答案依据和端到端成功率。如果每题只有一个标注相关段落，Recall@k 就退化成是否命中的 0/1。

这里假设实际返回了 kkk 条，且相关集合 RRR 非空。如果一题有 2 个相关段落，前 5 条召回只含其中 1 个，Recall@5 是 0.5，Precision@5 是 0.2。只看召回率，往往会倾向增加 k；但更大的 k 也会增加上下文长度、噪声和后续处理成本，所以应一起报告质量与成本。

对无答案问题，需要单独考察系统是否能拒绝猜测或请求补充信息，不能为了套用上式而伪造一个“相关段落”。

7.4 上下文预算与信息保留

实际计算还要考虑聊天模板、特殊 token 和接口定义的计数方式。不能把 len(text) 当 token 数。离线模型应使用对应的 tokenizer 和聊天模板；托管接口以其计数工具、文档以及响应 usage 为准。

应记录 tokenizer 名称和版本、截断策略、原始/保留 token 数。超限时优先移除重复检索结果、无关历史与冗长日志，保留当前任务、关键事实和工具执行状态。仅留下“最新几条消息”可能切断一次工具调用与它的结果。

例如，上下文上限设为 8192 token，预留输出 1024，那么输入最多 7168。若系统消息与工具定义合计 1600、历史 2200、当前问题 200，则留给检索资料的预算最多为 3168。这些都是假设的 token 计数，不是根据汉字数换算出来的值。

工程里还需要检查模型是否另有输出上限，并为模板变化留余量。预算分配应当是显式代码，而不是等模型接口报错后随机删一段文字。

8. 常见追问

词表越大越好吗？

更大的词表可能用较少 token 表示常见文本，但会扩大 embedding 与输出分类空间。还需要看语料覆盖、序列长度、训练统计和推理成本，不能只优化词表大小。

One-hot 与 embedding 查表是什么关系？

One-hot 乘 embedding 矩阵等价于取出对应行。前者方便描述数学关系，后者避免创建高维稀疏向量，是通常的实现方式。查表结果本身尚未融合本次上下文。

Word2Vec、ELMo 与句向量分别表示什么？

标准 Word2Vec 通常给词表内每个词一个固定向量；ELMo 让词在不同上下文中具有不同表示；句向量则把整段文本映射到一个向量，常为检索等任务专门训练。上下文化与面向检索训练是不同的性质。

为什么不同 tokenizer 的困惑度不宜直接比较？

困惑度按预测单元统计。一个模型把一个词编码成一个 token，另一个拆成三个，平均损失的分母和条件预测任务已经不同。还必须统一文本、特殊标记和有效位置等统计口径。

归一化后，余弦相似度、点积和欧氏距离怎样联系？

两个向量均为单位向量时，点积等于余弦相似度，欧氏距离的平方等于 2 减去两倍点积，因此排序可以对应。零向量不能正常归一化；不同模型的坐标空间也不能仅因维度相同而混用。

检索命中了相关主题，为什么仍可能答错？

主题相关不代表包含答案；候选段落可能缺少步骤、条件或时间范围。应依次检查目标证据是否存在、是否被召回、是否进入最终上下文，以及回答是否受到证据支持。
